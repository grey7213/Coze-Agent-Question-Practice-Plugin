## 1. 先验调研

**初始开发会话未能实时检索。** 下表保留当时的方案回忆；2026-10-29 已补充下方的当前检索与源码核对，不能把初始记录当作最新调研。

| 类别 | 代表 | 可借用 | 不采用 |
| --- | --- | --- | --- |
| ChatGPT 网页增强 | ChatGPT Box、WebChatGPT | 内容脚本 + 后台请求的分层，避免页面拿到 Key | 它们的目标是增强对话，不含题目识别 |
| 油猴答题脚本 | 各类 `auto answer` 用户脚本 | 单文件、选择器可配置的思路 | 直接 `innerHTML` 赋值，React/编辑器状态不同步 |
| 浏览器自动化 | Playwright / CDP | `Input.insertText` 是编辑器兼容性最好的路径 | 需要独立进程和调试端口，日常使用成本高 |

**关键结论**

- React 受控输入：必须用原型上的 `value` setter，再 `dispatchEvent(new InputEvent('input', {bubbles:true}))`。
- `contenteditable`：`element.textContent = x` 只改 DOM，不改编辑器内部模型；应优先 `document.execCommand('insertText', false, x)`，并回读校验。
- 发送：优先点真实的发送按钮；`Enter` 键盘事件是兜底（部分编辑器只监听 keydown）。
- 所有自动化都要「写后回读」，否则会把半截内容发出去。

## 4. DOM 自适应策略

现已读取真实登录态页面并完成填写验证。为适应 Coze 改版，保留不依赖混淆类名的启发式，并用真实结构夹具回归：

1. **滚动容器**：可见、`overflow-y` 为 auto/scroll、`scrollHeight > clientHeight + 80`、面积够大；按面积 + 文本量打分，排除左侧栏与整页布局。
2. **消息列表**：在容器内枚举元素，取「直接子元素 ≥ 2、可见、有文本、垂直有序」的候选，按子元素数量 + 覆盖容器高度的比例 + 文本量打分。
3. **消息行**：列表的直接子元素；若只有 1 个则向下递归最多 3 层（应对虚拟列表 / 单层 wrapper）。
4. **输入框**：`textarea`、`[contenteditable]`、`[role=textbox]` 中可见、尺寸合理、最靠页面底部的。
5. **发送按钮**：输入框附近、尺寸 12–120px、标签含 send/发送 的按钮优先；分数不够就不猜，退回 Enter。
6. **人工兜底**：面板「重新指定输入框 / 消息列表」用取色式点选，存 CSS 路径到 `settings.overrides`，失效时自动回退启发式。

## 5. 状态机

```
idle → running
  tick(700ms):
    读消息行 → 取最新非本人消息 → 文本 hash 稳定 ≥ stabilizeMs
      ├─ 命中继续提示 且 不是具体题目 → state=advance → (autoAdvance ? 发送「是」)
      ├─ 像题目 → state=question → (autoGenerate ? 生成)
      └─ 其他 → 忽略，不自动作答
生成 → answered → 自动填写 → filled
      ├─ requireConfirm=true  → ready，等人点发送
      └─ requireConfirm=false → sent
sent → 等待对方新消息
```

「像题目」= 含问号 / 第 N 题 / 请回答 / 选项行 `A.` 等；「继续提示」= `回复「是」`、`是否继续`、`继续下一题` 等。若消息同时像具体题目（含选项或「第 N 题」），按题目处理，避免把「下一题：……」当成进阶提示。

防重复：`handledKey`（已处理的文本 hash）+ `sentKeys`；本人消息文本记录在 `ownTexts` 里，不参与题目判定。

## 6. 大模型调用

- 协议：`openai`（`/chat/completions`）与 `anthropic`（`/v1/messages`）。
- 系统提示要求固定格式 `答案: …` / `解析: …`，解析失败时退化为整段文本。
- 上下文：最近 8 条消息，角色标注为「我 / 对方」，截断到 6000 字符。
- 超时 60s，`AbortController`。
- 权限：请求前 `chrome.permissions.contains({origins:[origin+'/*']})`，未授权时返回中文提示，引导去设置页授权。

## 8. 关键取舍

| 问题 | 选择 | 理由 |
| --- | --- | --- |
| 扩展 vs 油猴 vs CDP | 扩展 | 隔离世界稳定，能拿可选 host 权限直连模型；CDP 需另起进程 |
| 是否自动发送 | 默认人工确认 | 误答/误发代价高；全自动作为显式开关 |
| 是否内置 Key | 否 | 安全与合规 |
| 选择器策略 | 启发式 + 手动绑定 + 调试导出 | 已按真实 DOM 适配，仍需应对改版 |
| 是否用页面自己的 Coze bot 当大脑 | 否 | 用户选择外部模型推理；且页面接口未公开 |

## 9. 风险与对策

- **Coze 改版导致识别失败**：手动绑定 + 调试导出；`detect.js` 全是启发式，不依赖单一类名。
- **编辑器不响应 execCommand**：回读校验失败即报错，不发送；面板提示改用手动粘贴。
- **虚拟列表只渲染可视区**：只要求最新消息，天然可用。
- **流式输出**：`stabilizeMs`（默认 1200ms）+ 文本 hash 去抖。
- **API 费用**：上下文截断 + `maxTokens` 上限 + 最大轮数。

## 10. 2026-10-28 真实回归设计

2026-10-29 验证补充：复用 `real-flow.js` 的有界 CDP 连接和脱敏函数，增加独立真实会话验收入口。只读取必要状态，不导出存储或凭据；登录使用后台已配置的身份，手机号/验证码仍由用户处理。经现有面板按钮运行，默认保持确认且关闭自动进阶，显式发送测试逐次执行。截图需遮盖登录与设置字段；验收结果写入 `output/playwright/`。

本轮为既有缺陷修复，直接以当前源码、真实 Coze DOM 和 Chrome CDP 结果为依据。

- 已连接 Chrome 156 的独立调试配置，并进入真实答题页。消息区、输入框和页脚共享深层祖先，不能因为祖先包含 textarea 就跳过整棵子树；优先寻找输入框附近的实际聊天滚动区，区分消息列表、消息正文与页面外壳。
- 真实消息的 DOM 顺序可能与视觉顺序不同，需按真实容器布局核对并形成脱敏夹具；新消息不能被旧判分反馈或页脚替代。
- 状态机只可跳过页面噪音。最新本人消息、判分反馈或结束消息是历史边界，不能越过它们重新执行旧题和旧「继续」提示。发送成功后记录已处理消息，慢回复期间不重复提交。
- 保持 `requireConfirm=true`、`autoAdvance=false`。真实模型验证通过扩展后台和已授权的配置 origin，绝不记录密钥和学生身份。
- 本地配置由扩展后台读取并导入存储，不作为 `web_accessible_resources` 暴露给 Coze 网页；离线测试包排除 `tools/` 和 `output/`，使用虚构凭据。
- CDP 请求设置有界超时；真实诊断输出和文件脱敏；截图存入 `output/playwright/`。窗口最小化时恢复目标调试窗口，截图失败单独报告，不能让诊断命令永久等待。
- 真实顶层长期保留，iframe 在知识点/答题页切换时被重建。子 frame 持续宣告、离开时注销，顶层按存活时间剔除旧目标并优先选择有输入框的 frame；扩展运行时通过后台按 `sender.tab.id` 中转，避免同源多个标签页的 BroadcastChannel 相互干扰。普通网页测试仍保留 BroadcastChannel 兜底。

## 11. 2026-10-29 暂停与发送一致性

本轮先在当前机器复跑既有七套测试，基线为 97/97（包括真实模型）。继续检查发现，现有测试尚未覆盖用户暂停时模型请求未完成、写入被截断、填写期间连点发送等情况。

- 引擎为异步动作记录递增版本。暂停、重置、跳过使旧版本失效；旧 Promise 完成后不得写入、发送或覆盖新动作的状态。
- 每次生成绑定当前消息标识、文本及输入框。模型返回、填写结束、延迟发送前都重新校验；页面换题或输入框被替换时等待重新识别。
- 发送锁在第一次异步填写之前取得，发送流程结束后释放；已点击的消息标识保留，避免慢回复时重复发送。
- `fill.js` 对完整答案做一致性比较。发送验证只接受输入框真正清空，不将“文本被截断/替换”视为成功。
- 跳过使用和扫描相同的消息标识算法，并清除待发送答案；暂停后已有完整草稿可在重新开始时恢复确认状态。
- 使用真实 Chrome 内的可控延迟模型和输入事件构造回归；先记录失败，再修复并跑完整七套测试。保持 `requireConfirm=true`、`autoAdvance=false`。
- 真实 Coze 验收与自动化回归分别记录。用户后来已在受管 Chrome 加载扩展 #13 并完成登录，真实生成和填写通过；该浏览器没有提供 9222 调试端口，不把脚本连接失败当作插件故障。

- [Chrome 官方扩展示例](https://github.com/GoogleChrome/chrome-extensions-samples)：实时确认 Apache-2.0、未归档，最近推送 2026-10-27。沿用 MV3、后台消息和浏览器原生存储，不增加第三方运行时依赖。
- [Radix Select 源码](https://github.com/radix-ui/primitives/blob/main/packages/react/select/src/select.tsx)：核对 `SelectTrigger` 的键盘展开与 pointerType 判断。真实 Coze 使用 `button[role=combobox]`、`aria-expanded`、Radix `role=listbox`。已在真实页面证明 `focus + keydown ArrowDown` 能展开。选项以焦点和 Enter 选择，并回读触发器文本确认，不能只认 click 返回成功。
- 只复用公开接口与设计思路，没有复制整库或新增依赖；未对第三方仓库作完整安全审计。
- 真实答题页：判分含 `你的答题结果是：正确`、`本题得分：2`；知识点在 `考查知识点：【…】` 或 `本题考查的知识点：…`。商店侧的资源积分不是学生得分，不能混用。
- 已由真实扩展 #13 生成并填入 `A：大`，确认模式没有自动发送；显式发送后输入清空，Coze 返回 `资源点余额不足，请等待额度刷新或升级到专业版`。此消息不是判分，不得推断章节完成。
- 真实 `返回上一页` 可到知识点页；键盘可展开下拉，但当前 `listbox` 显示 `暂无数据`。后续真实判分及下一章出题受平台可用状态限制。

### 模块与状态

- 新增 `src/core/chapters.js`：判分解析、章节名归一化、已完成集合、下一项选择与可中止的 DOM 导航。
- 引擎在处理继续提示和新题之前让章节流程检查最新反馈；必须有明确正确标记和零新增分值，缺失分值绝不当 0。只检查最新对话边界，避免历史零分触发切换。
- 状态为 `idle → checking_score → returning → selecting → starting → answering`；无剩余项进入 `complete`，平台错误/空列表进入可重试的 `error`，用户暂停中断未执行的下一步。
