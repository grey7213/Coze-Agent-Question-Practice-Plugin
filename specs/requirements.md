# Coze 答题助手 — 需求

## 目标

在浏览器里给 Coze（扣子）对话页加一个浮动面板：识别对话中最新出现的题目，调用用户自己配置的大模型生成答案，把答案写入 Coze 的输入框；默认由人确认后再发送，可选自动回复「是」进入下一题。

## 用户

- 使用 Coze 机器人做题 / 练习的中文用户。
- 愿意自备 OpenAI 兼容或 Anthropic 的 API Key。
- 能按 README 手动加载未打包扩展。

## 场景

1. 机器人发来第 N 题（可能带 A/B/C/D 选项）。
2. 扩展识别到该消息，生成答案并显示在面板里。
3. 扩展把答案填进输入框，等待用户点「发送」（默认）。
4. 机器人回复「回答正确，是否继续？回复『是』」。
5. 扩展识别到继续提示，用户点「发送『是』」（默认），或开启自动后自动发送。

## 非功能需求

- 隐私：API Key 只存 `chrome.storage.local`，只在后台请求时使用；不上传到任何第三方；调试导出不含 Key。
- 权限：仅 `storage` + 可选网络权限；网络权限在设置页由用户点击授权。
- 性能：轮询 700ms，整页扫描最多 5s 一次；单页 CPU 开销可忽略。
- 兼容：Chrome / Edge 116+（MV3）。
- 可维护：核心 DOM 逻辑与 UI、chrome API 解耦，可在普通网页里跑集成测试。

## 非目标

- 不做 canvas / 图片题 OCR。
- 不做绕过登录、绕过反作弊、隐藏痕迹。
- 不做无人值守的全自动考试提交；全自动开关默认关闭，需用户显式打开。
- 不内置任何 API Key 或答案库。
- 不保证适配 Coze 之外的站点（通用启发式可用，但未验证）。

## 风险

- Coze 前端是 Semi Design + 混淆类名，改版频繁；选择器必然需要人工兜底。缓解：启发式 + 手动绑定 + 调试导出。
- 大模型答案可能有误；默认人工确认就是对冲。
- 用户若开启全自动，可能违反课程或平台规则，由用户自行承担；README 明示。
